# Промпт: полировка DEE B2B — UX, стиль, стек (БЕЗ полного редизайна)

Скопируй всё ниже в новую сессию Claude Code в папке `Dee B2B` — или скажи: «Выполни NEXT-SESSION-PROMPT.md».

## Цель и рамки

Довести портал DEE B2B до состояния «удобно, логично, просто и быстро» перед включением в полную работу. Это **полировка, не редизайн**: бренд DEE (его палитра, характер, дух) остаётся как есть — меняются качество исполнения, консистентность и UX. Приложение ещё не в полной эксплуатации — это окно для стековых правок, дальше их цена вырастет в разы.

Планка качества — `../_Instructions-Web/` (02 ритм, 03 типографика, 06 состояния, 07 анти-слоп): применяем их **дисциплину**, но НЕ студийные токены — у DEE свой бренд и свой CLAUDE.md, он приоритетнее.

## Стек — решения приняты (Вова делегировал; если что-то смущает — подними вопрос ДО Фазы 1, потом не пересматривать)

**Меняем (окно пре-продакшена):**
1. **Next.js 15 → 16**, **npm → pnpm**, **+ Biome** (вместо ESLint/Prettier, если стоят) — без визуальных изменений, чисто тулинг.
2. **JS → TypeScript strict** — помодульно, механически: `lib/` → компоненты → `app/`. Бизнес-логика (VAT, shipping, e-conomic) при миграции не «улучшается» — только типизируется.
3. **Inline styles → Tailwind v4 с сохранением внешнего вида**: извлечь ФАКТИЧЕСКИЕ значения DEE-бренда (цвета, отступы, радиусы, шрифты — как они есть в inline-стилях сейчас) в `@theme`-токены и мигрировать экран за экраном со скриншот-диффами до/после — пиксельная близость, а не новый лук. Это снимает последнее большое отклонение от студийного стека, не трогая дизайн.
4. **shadcn/ui на Base UI — только точечно**: там, где UX-фикс всё равно требует переделки контрола (диалоги, селекты, тосты, формы) — берём примитив ради клавиатуры/фокуса/a11y и красим в DEE-токены. Wholesale-замену компонентов не делать.

**НЕ меняем:** Railway Postgres + raw SQL через `postgres` (работает, ORM не нужен), jose OTP-auth, Resend, jsPDF, e-conomic-синк, Railway-хостинг, домен. Логику VAT/shipping и claim-locking — только читать; правки там — отдельными явными задачами, если Фаза 0 найдёт баги.

## Правила репо (из его CLAUDE.md — прочитай его первым)

Standing-правило: коммит + пуш + деплой в той же сессии. Тесты (vitest) зелёные перед пушем. Проверка интерактива — на `pnpm build && pnpm start`, не только dev.

## Фаза 0 — аудит глазами нового клиента

1. Прочитай `CLAUDE.md` репо целиком; подними приложение локально (dev И build+start).
2. Пройди КАЖДЫЙ флоу как клиент, который видит портал впервые: логин по OTP (включая «письмо не пришло», опечатку в коде, повторную отправку) → каталог → корзина → оформление (VAT, доставка) → подтверждение → история заказов → повторный заказ → claims/рекламации (если есть) → выход. И как админ — все админ-флоу.
3. Скриншоты каждого экрана (headless Playwright), каждого состояния: обычное, пустое, загрузка, ошибка, мобильная ширина 375.
4. Собери приоритизированный список: (а) UX-трение — лишние шаги, неочевидные действия, отсутствие обратной связи; (б) несуществующие состояния — empty/loading/error, которых нет; (в) визуальные несоответствия — разные отступы/радиусы/кегли на одной роли, кривые выравнивания; (г) медленное — по Lighthouse (LCP/CLS/INP) на build-версии; (д) баги.
5. **Покажи список Вове с приоритетами** (что чинится в этой волне, что позже) — дальше работай сам.

## Фаза 1 — стек (по решениям выше)

Порядок: Next 16 + pnpm + Biome → прогон всех флоу (регрессий ноль) → деплой. Потом TS помодульно (каждый модуль — компилируется + тесты). Потом Tailwind-токенизация экран за экраном: скриншот-дифф до/после на каждый экран, расхождение — только осознанное (из списка Фазы 0). CHANGELOG на каждый шаг.

## Фаза 2 — UX-фиксы по списку Фазы 0

- Каждый экран с данными получает честные empty/loading/error (skeleton повторяет вёрстку — 06).
- Формы: валидация инлайн после blur/submit, понятные ошибки, autoFocus, Enter работает, disabled-состояния на сабмитах, двойной сабмит невозможен.
- Обратная связь на каждое действие: сохранение, добавление в корзину, отправка заказа — видимый отклик ≤ 100ms (optimistic где уместно).
- Скорость: Server Components по умолчанию, `next/image` на все изображения, динамические импорты тяжёлого (jsPDF!), кэширование каталога. Цели: LCP < 2.5s, INP < 200ms на build.
- Мобильная: все флоу проходимы на 375px, таблицы скроллятся в контейнере.
- Клавиатура: полный обход Tab, видимый фокус, Esc закрывает диалоги.
- Копирайтинг: все user-facing тексты через скилл humanizer — на языке(ах) портала; кнопки-глаголы, без восклицаний.

## Фаза 3 — стиль «в лучшую сторону» в рамках бренда

Не новый дизайн — наведение ремесла в существующем:
- Один ритм отступов на всём портале (шкала из фактических DEE-значений, приведённых к сетке), «почти одинаково = баг».
- Одна типографическая шкала: убрать случайные кегли/веса; tabular-nums на ценах, суммах, количествах — это B2B, цифры везде.
- Единые радиусы и тени по ролям; hairline-разделители вместо случайных теней.
- Спроектированные hover/active/focus-visible на всём интерактивном.
- Motion — только по бюджетам 05 (150–350ms, смена состояния); ничего декоративного. Живой слой из 10 сюда НЕ тащить — это рабочий инструмент клиента, тишина уместнее.
